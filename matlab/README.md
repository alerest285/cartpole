The full-course builder creates LQR, pole placement, PID, mouse catch, fixed sine,

logic and adds applied-voltage logging. The controller uses raw encoder positions,
unwraps the angle and estimates velocity with the same Kalman parameters as Python.
All models start Arm=0 with a 4 V cap. Sine/Identify excitation starts at 1 V.
The `Tuning` constant is documented by the builder and `cp_lab_controller.m`.
Run `validate_course` on the licensed machine before compiling any QUARC model.

or the new models' `lab_state`/`lab_voltage` logs. For the shared Python fit and gain export:

## Start after activating MATLAB

Set MATLAB's Current Folder to this `matlab/` directory, then run:

```matlab
demo_cartpole
```

This first checks Python reference vectors, then runs LQR, pole placement, PID, energy swing-up, phase-locked sine swing-up and the current trained PPO policy for 12 seconds each. It plots the results, asserts that each finishes balanced, saves `results/simulation_results.mat`, and animates the energy swing-up. Base MATLAB is sufficient; no Python integration or toolbox is needed for these simulations.

For one simulation:

```matlab
r = simulate_cartpole('energy', 12);
animate_cartpole(r);
```

The loop runs at 500 Hz with two RK4 plant substeps, encoder quantisation, the Python Kalman filter equations, a voltage cap, track barrier, hard stop and optional actuation delay. States are `[x; alpha; x_dot; alpha_dot]`; alpha is zero upright, counter-clockwise positive, and hanging is +/- pi. PPO runs every tenth control tick (50 Hz), with the same observation scaling and policy weights as Python.

To test model mismatch, keep the controller model unchanged and edit the true plant:

```matlab
c = cp_config();
c.truth.B_f = 3.3;
c.truth.k_amp = 0.93;
c.truth.delay_steps = 1;
c.truth = cp_derive(c.truth);
r = simulate_cartpole('energy', 12, c);
```

## Simulink simulation

```matlab
build_cartpole_simulink('energy')
validate_simulink
```

The builder saves `generated/cartpole_sim.slx`: a 2 ms discrete feedback loop with scopes and workspace logs. It uses the same MATLAB core through an Interpreted MATLAB Function block. It is a normal-mode simulation model; it is not a QUARC target or a code-generation model. Run the builder to initialise its workspace before opening/running the saved model. `validate_simulink` compares all 6,000 samples against the native MATLAB loop.

## Earlier LQR-only QUARC alternative

On the lab PC with MATLAB, Simulink, Control System Toolbox (for gain redesign) and QUARC:

```matlab
setup_lab
build_course_lqr
```

`build_course_lqr` fills a COPY of `course_original/state_feedback_controller.slx`, saved as `generated/cartpole_lab_lqr.slx`. It wires `[x, alpha, x_dot, alpha_dot]` and the course reference signals into `-K*s`, adds an Arm constant initially **0**, a **4 V** cap, and workspace logs. The original protected I/O subsystems, angle gate, saturation and position watchdog remain intact. The function never builds, downloads or runs the hardware model. Build/compile and rig verification are still pending. QUARC startup may initialise the board even with Arm=0; stop Python first.

This route uses the course's 60 rad/s derivative filters. It is a separate validation path from the Kalman-based simulations; don't assume the same measured performance. Check signs and timing, then build/connect in QUARC with the TA and lift the pole upright before enabling Arm. `lab_command` is before the course angle gate, not measured motor voltage.

The prepared QUARC controller is LQR balance only. Energy, sine and PPO are available in MATLAB simulation and through the Python hardware pipeline. `lyapunov.m` remains the handout's simple MATLAB Function block example, not the full energy controller in `cp_control.m`.

## Refresh parameters, gains and policy after a rig session

From the project root, using the project's Python environment:

```text
python -m cartpole sysid
python -m cartpole improve --iters 300
python tools/export_matlab.py
```

`export_matlab.py` writes `generated/contract.json` from the accepted fitted plant, the current policy, and the hardware map. It also writes model, safety, estimator and controller replay vectors from Python. Run `validate_cartpole` after each export; rerun `build_course_lqr` to bake updated gains into the copied hardware model. Export and rebuild only while disarmed.

`setup_lab` imports ready-made gains without requiring Control System Toolbox. `design_gains` independently recalculates gains with `place`, `lqr`, and `dlqr`; its inputs now come from the shared contract. The course's older Desktop `.m` files use an earlier simplified model; use this folder for the shared simulation.

Every new Python runtime recording includes `.csv`, `.npy` and `.json`; PPO exploration adds `.ppo.npz`. For plots in MATLAB:

```matlab
run = load_cartpole_run('../runs/YOUR_RUN_ID.csv');
```

Keep the original NPY/JSON/NPZ files for Python system identification and PPO. MATLAB's course-model workspace logs have a different schema and are not automatically imported into PPO.
